# Memory Style Guide

## 定義

Memoryは写真の説明やキャプションではなく、写真と閲覧者の間に置かれる余白です。写真に写っている事実を言い換えるのではなく、ひとつの情景だけを残し、その先を読む人に委ねます。

評価するのは写真の良し悪しではなく、Memoryの文体です。自動生成・自動評価は行わず、人がA / B / C / NGと任意コメントを付けます。

## 良いMemory

- 情景や気配をひとつだけ置き、説明を加えない
- 読み手が別の解釈をできる余地を残す
- 写真に実際に写る具体的な手がかりを起点にする
- 場所や人物を知らなくても文として成立する
- 短く、写真を見る時間を奪わない
- 他のMemoryと似た言い回しを繰り返さない

例:

- 海風だけが残っていた。
- 人の流れが落ち着く頃。
- 灯りだけが水面に揺れていた。
- 少しだけ立ち止まる理由があった。

Favorite Memoryは20〜40文字程度を目安にします。長さだけで評価を決めず、写真の説明になっていないこと、余白があることを優先します。

候補を複数作る場合は、時間、光・色・空気感、気配・余韻・距離感のように異なる方向を探します。方向の指定は写真にない内容を作る理由にはせず、すべて実際に見える手がかりを起点にします。

## 避ける表現

- **説明:** 写真に写る対象や撮影状況を説明する
- **感情の断定:** 人物やキャラクターの気持ちを決めつける
- **固有名詞:** 場所名、人物名、キャラクター名を書く
- **ストーリーの固定:** 写真にない出来事や背景を事実のように語る
- **撮影行為:** 撮影したことや写真であることを述べる
- **メタデータからの推測:** 場所やタグの一般的なイメージを、写真に写っている事実として扱う
- **装飾しすぎ:** ポエムや小説のように意味を重ね、写真より言葉を目立たせる
- **汎用表現の反復:** どの写真にも当てはまる同じ文を使い続ける

悪い例:

- ○○で撮影した。
- ○○が楽しそうだった。
- ○○は帰りたくなかった。
- イベント帰りだった。

## 評価の目安

| 評価 | 判断の目安 |
|---|---|
| A | 情景が静かに立ち上がり、説明せずに想像の余地を残している |
| B | 方向性は合っている。少し整えると、より自然で固有の余白が生まれる |
| C | 説明的・抽象的・反復的、または写真固有の手がかりに結び付かず、想像を広げにくい |
| NG | 禁止事項に触れる、またはMemoryとして成立していない |

コメントは判断の理由や編集の方向を短く記録します。例:「余白がある」「説明的」「場所に依存している」。評価は人が行い、評価結果を自動で生成文へ反映しません。

候補を採用する前に、Copilotが示した「視覚的な手がかり」が写真に本当に写っているか確認します。手がかりが場所・タグからの推測だったり、候補が写真に固有の要素と結び付いていなかったりする場合は採用せず、再生成します。

## Libraryと分析

評価時点の本文を `memory-library.json` にスナップショットとして残します。Session MemoryとFavorite Memoryは種類を区別して保持し、本文が後から変更されても過去の評価を失いません。評価またはコメントを変更すると新しいスナップショットが追記され、現在の評価には同じ対象・本文の最新レビューを使います。同じ評価とコメントの再保存では重複記録を作りません。

Analyticsは評価分布、文字数、頻出表現、重複、A評価、NG、未評価を確認するための補助です。集計値だけで良し悪しを自動判定せず、最終判断は必ず人が行います。

将来AIへ接続する場合も、A / B評価は参考例、C / NG評価は避ける表現の例として利用できます。評価データを生成モデルへ渡す処理は別途明示的に設計し、自動生成・自動評価は追加しません。
